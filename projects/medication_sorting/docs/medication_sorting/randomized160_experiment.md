# 四药品160条随机示范实验

本实验保留旧场景、旧单药盒数据和模型，单独测试四药品策略。两个药盒保持尺寸，两个药瓶为原尺寸70%；固定基座G1只使用右臂和夹爪。不能把结果推广为原尺寸药瓶或真实机器人效果。

## 数据与训练

- 每种药品40条合格示范，共160条。按完整回合分层为每种32条训练、8条验证，共128/32条。
- 每回合只在初始化时改变目标摆放：相对其初始位置每轴正负2cm、绕竖直轴正负15度，保持直立。不是整张桌面任意摆放或倾倒姿态。
- 双视角实际RGB与8维机器人状态、动作同步保存。相机是原生视口俯视和虚拟手端跟随，不是物理安装的腕部相机。
- 抓取、落筐或图像质量失败的回合保留，但不进入训练；缺额补采。最终成功率必须包含失败尝试的分母。
- 从官方π0.5基座重新做LoRA微调，20,000个优化器步，不是20,000个完整epoch；batch size为1，action horizon为10。
- 统计量只使用训练集。验证回合不进入训练和统计量。

新专家配置为`randomized_tabletop_70`；旧`scaled_bottles_70`保持原参数。饮品盒改为张开夹爪接近，随机抓取方向随物品转角调整，搬运向固定落筐姿态回正。随机物理预试仍有不可达和放置失败，必须按真实结果记录。

## 自动执行

入口：`tools/medication_sorting/run_randomized_experiment.py`。依次执行采集、严格分层、LeRobot转换、训练集统计量、20,000步训练、真实检查点部署和40次推理。

长任务由用户级systemd服务管理，与Codex终端会话分离。每四次尝试结束后备份编辑场景、停止自己启动的OrcaLab，再开新批次；不会停止其他项目的Python或占用已有策略端口。连续三批无新增合格示范或任一物品用完200次尝试仍不足40条时，停止并报告错误，不启动训练。

只有采集阶段支持按原配置断点补采。转换、训练和评估中断后需要先检查已产生的文件，再单独恢复相应阶段；不能直接重跑整个入口覆盖已有输出。服务配置为`Restart=no`，不自动循环重试。

场景初始化增加最多三次有限重试：启动或MCP加载失败时，仅备份、退出本任务自己启动的窗口再试；不接管外部占用端口的窗口。该重试发生在采集/评估回合运行之前，不重放已经执行的训练或推理回合。

## 推理验收

每种药品10个全新随机摆放，共40个独立重置回合；每回合只执行目标药品任务。策略只接收图像、机器人状态和任务文本，目标真值仅用于初始化和验收，没有专家动作回退。

成功必须具备双指接触并抬起超过6cm、松爪后物体完整落入正确筐底范围、速度低于0.02m/s并持续稳定。模型返回动作、训练损失下降或服务启动不算成功。所有40次均纳入分母。

未完成同一场景连续分拣四件物品，因此不报告连续整理成功率。
