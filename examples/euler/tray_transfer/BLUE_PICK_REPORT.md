**夹爪可以工作。保留原资产的碰撞、接触和质量参数，改用官方 joint2 控制后，蓝件已抓离桌面并保持。** 最后一秒最大接触压入约 4.71 mm，全流程达到约 10.27 mm，均超过本项目设定的 2 mm 上限，因此严格验收仍为失败，尚不能记作合格专家数据。此前把旧控制方案的失败直接归因为原模型夹爪失效，证据不足，现予以纠正。

## 当前控制与测试条件

- 环境：`orcalab_9_1`，OrcaLab/OrcaGym 26.9.1，MuJoCo 3.12.0，CPU Euler；物理步长 2 ms，控制周期 20 ms。
- 模型：当前场景导出的 XML 与 STL；蓝件质量约 0.788 kg，窄边约 47 mm。保留原有执行器、四连杆约束及碰撞接触参数，固定 pelvis 作为桌面测试条件，并未验证站立平衡。
- 夹爪：只驱动 `idx79_gripper_r_inner_joint2_pctrl` 和 `idx89_gripper_r_outer_joint2_pctrl`。两者接收相同输入，张开 `-1`、参考闭合 `2`；其余六个执行器输入为 `0`，仍保留原有伺服，并非被动关节。
- 手臂：沿用已检查的 IK 路点；29 个非夹爪关节使用广义偏置力补偿及位置误差反馈。`qfrc_bias` 包含重力和速度相关项，不包含自由工件经接触传递的全部负载。原始控制范围和力矩限制保留。
- 动作：张开 → 先抬手避开灰件 → 转到预抓位 → 45°斜向进近 → 闭合 → 末端抬升 15 cm → 保持 4 秒。抓点为蓝件 body 局部 `[0, 0.04, 0.11] m`；灰件不参与任务，仅作为障碍物。

夹爪输入是执行器命令，不能直接赋给 qpos，也不能与早期 joint1 参数化的几何标定角混用。控制依据为[官方执行器配置](https://github.com/openverse-orca/SouthGrid/blob/7e98424bc3726b82f73aad66dc1e714e8dbe60fb/src/conf/g1_pick_osc_conf.py#L90-L97)和[官方开闭值定义](https://github.com/openverse-orca/SouthGrid/blob/7e98424bc3726b82f73aad66dc1e714e8dbe60fb/src/examples/dataCollection/unitree_g1/g1_pick_osc_collection_scripted_lerobot.py#L89-L91)。本项目的名称映射见 [gripper_control.py](gripper_control.py)。

整个动作通过关节伺服和物理步进完成。没有将物体焊到手上，没有在动作过程中设置物体位置、修改质量或施加向上辅助力。

`result.json` 中 `passed=false`，未通过的是接触压入相关检查。该轮控制输入与执行器力矩饱和计数均为 0。完整碰撞体的离桌高度用于避免把物体倾倒后的原点升高误判为抬起。

**最后一秒的数据不能代表整条轨迹的质量。** 复查全流程 trace，闭合阶段最大压入约 9.48 mm，闭合保持阶段约 9.74 mm，抬升阶段约 10.27 mm；抬升后的蓝件倾斜约 51.8°。即使最后保持较稳定，当前轨迹也尚不适合作为优质专家示范。

当前结果判定已加入全流程目标物接触压入检查。`trajectory_metrics` 记录峰值、阶段和时间，`trajectory_target_penetration_under_2mm` 也必须通过；避免早期严重压入被最后一秒的稳定保持掩盖。全流程峰值出现在抬升阶段约 20.38 秒处。

在相同手臂路径下，降低闭合输入到 `0.5`、`1`、`1.5` 的对照均未稳定夹起蓝件。输入为 `1` 时，物体原点虽上升约 67 mm，实际已倒伏且仍由桌面支撑，不能计为抓起。因此目前还不能把减小输入作为已验证的改进；需要继续检查抓点、指面实际姿态和闭合过程。该结果不支持“原夹爪不能使用”的结论，也不能直接作为训练数据质量合格的证据。

旧实验排除了 inner/outer 各自的 `link1↔link2`、`link4↔link2`，并将两个指尖的 `solref` 从 `0.02 1` 改为 `0.005 1`、`priority` 从 0 改为 1、`condim` 从 3 改为 4、`friction` 从约 `2 0.1 0.1` 改为 `2 0.01 0.1`。滑动摩擦系数原本就是 2，并未增大。

这些多变量实验不能证明每项改动是必要的，也不是已确认的资产修复。仅观测到连杆内部接触，不能判断它阻止了正常开合。新控制已在保留这些接触的条件下抓起蓝件。

## 如何复现和检查

当前命令见 [README](README.md#先复现蓝件测试)，默认使用 `--profile original`。本轮可复现的严格判定为退出码 2，原因是上述压入阈值未通过。每次运行生成独立目录，含：

- `manifest.json`：源模型及引用资源 SHA256、控制器、实验参数、软件版本和固定底盘条件。
- `plan.json`：该次运行实际使用的路径和夹爪驱动配置副本。
- `scene.xml`：引用本机资源的测试副本。
- `trace.json`：50 Hz 位姿、相对夹爪位姿、接触力和最低碰撞体高度。
- `controls.npz`：控制步前后 qpos、名义动作、末子步伺服输入及时间。
- `result.json`：逐项验收、控制器标识及饱和计数。

源 XML、资源和运行结果未上传 Git。`blue_pick_plan.json` 绑定当前布局、源 XML、资源和初始关节；夹爪阶段保存执行器 `drive`，手臂阶段保存关节路点。移动物体后需要重新规划，它不具备摄像头识别或 cuRobo 重规划能力。

达到既定压入和稳定性判据后，再完成搬入木托盘、释放、退手及静止检查，最后加入起始位置随机化和每回合重规划。

π0.5 数据需要同步相机图像、机器人观测、任务文本、动作和 episode 边界；目前没有录制这些数据。训练与部署必须沿用相同的控制语义，尤其不能把夹爪 joint2 输入、实际关节角和八维几何标定目标混为同一个动作标签。cuRobo 可以优化路径规划，不能替代接触和实际控制验证。
