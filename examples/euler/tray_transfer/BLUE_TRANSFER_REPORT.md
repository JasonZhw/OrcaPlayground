# 蓝件搬入托盘：后续验证记录

日期：2026-10-27。分支：`feature/Synthetic_Data`。环境：`orcalab_9_1`。

**完整搬运尚未通过。** 夹爪可以把蓝件抓离桌面，但当前抓姿在继续抬升时会滑脱；手臂走完放置路点，不代表物体已放进托盘。本轮没有生成合格专家示范或 LeRobot 数据。

所有动态实验均使用当前导出场景的离线 Euler 副本，固定 pelvis。没有控制 OrcaLab 窗口中的机器人，没有修改用户的 Layout、源 XML、物体质量或摩擦，也没有在动态过程中将蓝件焊到手上或直接设置蓝件位置。

## 两轮物理实验

两轮均执行同一个 67 秒候选计划：原试抓 → 左臂避让 → 右手额外抬高 12 cm → 搬运及降低 → 松手 → 退手 → 静止检查。右夹爪继续使用官方 joint2 输入：闭合 `2`、张开 `-1`。

| 检查 | A：只固定 pelvis | B：另加固定腰部夹具 |
|---|---|---|
| 初始抬升、保持结束 | 蓝件离桌，仍有夹持 | 蓝件离桌，仍有夹持 |
| 左臂避让结束，35 s | 蓝件已重新接触环境，支撑约 4.38 N | 蓝件仍悬持，环境支撑 0 N |
| 继续抬高结束，40 s | 蓝件仍接触环境 | 蓝件滑脱，夹爪接触力 0 N |
| 腰 pitch 最大绝对偏角 | 29.84° | 0.00925° |
| 控制输入发生裁剪的控制步 | 956 | 0 |
| 最终托盘底板支撑力 | 0 N | 0 N |
| 最终其他物体支撑力 | 约 7.73 N | 约 7.73 N |
| 最终放置验收 | 失败，蓝件在托盘外 | 失败，蓝件在托盘外 |

**A 暴露了躯干控制问题。** 固定 pelvis 仍允许三个腰关节运动。当前腰 pitch 伺服增益约 28.501，命令范围约 ±0.52；在腰接近零位时，这个控制映射不足以提供当时约 29.49 Nm 的偏置补偿，输入被裁剪，上身明显前倾。这里不能直接推断真实电机力矩不足。

**B 将腰部姿态问题与抓取稳定性问题分开。** `--fix-waist` 在派生 XML 中显式增加三个腰关节的 equality 约束，`polycoef="0 0 0 0 0"`、`solref="0.002 1"`；接触参数仍用 `original`。这是固定躯干的台面实验夹具，不是站立平衡控制，也不能称为未修改原模型的结果。记录表明腰部偏转受到限制，但蓝件仍在额外抬升阶段滑脱。

B 同时修正了采样时序：每个控制步后调用公开的 `mj_forward()`，再统一读取位姿、接触和 Jacobian。A 的旧采样可能相对 qpos/time 落后一个 2 ms 物理子步，因此两轮不是只有腰约束一个变量的严格 A/B 实验；30° 与 0.00925° 的腰偏转来自各自保存的实际 qpos。

B 的初始保持也未通过质量门槛：最后一秒相对位置漂移约 5.44 mm、最大压入约 5.17 mm；全流程最大压入约 10.21 mm。当前阈值分别为 5 mm 和 2 mm。即使尚未掉落，也不能据此采集优质示范。

## 已完成的静态路径检查

直接向左搬运会遇到躯干、左手或关节限制。离线检查找到一个候选方案：左臂先避让，蓝件最终在托盘内直立，整个碰撞包围盒距内壁最少约 23 mm，底面在托盘底板上方 20 mm 时松手。

- 托盘使用落稳后的实际位姿；其 body 高度约 0.67167 m，不能直接沿用编辑器中的初始高度。
- 搬运候选使用 RRT-Connect，得到 177 个关节采样点；这不是 cuRobo 接入结果。
- 用实际夹爪张开后的几何检查松手过程。直接倒放搬运路径会擦到蓝件，改为先向上退手 5 cm 的候选。
- 静态检查仅假设蓝件保持已测得的相对夹爪姿态，用于预测碰撞；没有验证抓持力。动态中蓝件滑落后，这个假设不再成立。

这些是离散采样的运动学检查，不是连续碰撞证明，也不代表已完成物理放置。当前默认 `blue_pick_plan.json` 仍是单件试抓；失败的搬运候选没有替换它。

## 抓点优化尝试

按官方开合后的指面参考中心修正 TCP，比早期标定的末端局部 Z 多约 6.25 mm。仅修正 TCP、保持旧抓点局部 `[0, .04, .11] m` 的候选通过了本轮 IK 和碰撞检查，但动态试抓仍滑脱。

蓝件质心局部 Z 约 62 mm；旧抓点高度 110 mm、偏向局部 Y=40 mm。新的候选尝试夹在更低、更靠近中心的实体侧壁，减少偏心。固定当前机器人和物体位置，每个候选用了 4 个起点、每次最多 300 次求解评估：

| 蓝件局部抓点，m | 进近方向相对水平面向下倾角 | 最佳位置残差 |
|---|---:|---:|
| `[0, .02, .09]` | 30° / 45° / 60° | 14.72 / 11.21 / 22.31 mm |
| `[0, .02, .08]` | 30° / 45° | 20.02 / 15.63 mm |
| `[0, .03, .09]` | 45° | 5.91 mm |

均未达到 1 mm 门槛，因此没有把超差解当作路点执行。前五个近似终点还有蓝件与手指连杆穿入；最后一个未发现超过 0.1 mm 的外部穿入，但精度仍不合格。这只能说明这六个候选和有限求解未达标，不能证明所有抓姿都不可达。

## 验收逻辑

整体结果分别检查抓起质量、搬运期间保持、最终释放后的放置，再合并判定。三个阶段不能互相补分。

- **抓起**：物体原点和最低碰撞面均已离开初始支撑面；双侧指尖有有效接触；无其他支撑；保持漂移和全流程目标接触压入低于门槛。
- **搬运**：从 `lift_hold` 结束到 `release` 开始，预期阶段完整、时间连续；双侧指尖各至少 0.5 N，非指尖支撑低于 0.1 N，相对夹爪漂移不超过 5 mm / 5°。这对应本候选“悬于底板上方再松手”的方式，不适用于有意先触底再松手的计划。
- **放置**：最后连续一秒内，完整碰撞包围盒的 XY 位于托盘内部并留 20 mm 边距；底面位于底板附近；已脱离夹爪、由底板支撑而非桌面或栏杆；线速度低于 0.01 m/s、角速度低于 0.1 rad/s。
- 非有限测量、缺失阶段、过大的采样间隔均不能判成功。验证采样频率为 50 Hz，并未逐个检查 500 Hz 的全部物理子步。

新增搬运检查用于防止“曾经抓起、途中掉落、最后碰巧落进托盘”被判为成功。两次原实验本来就未通过最终放置，原始结果保留，不回写成新代码运行的结果。

相关 69 项离线单元测试和局部 Ruff 检查通过。它们验证数据读取、夹具标记及验收逻辑，不代表物理任务通过。

在本机复查固定腰部候选：

```bash
conda activate orcalab_9_1
cd ~/SY/OrcaPlayground
python -m examples.euler.tray_transfer.blue_pick \
  --model-xml examples/euler/tray_transfer/outputs/gripper_calibration_20261027/current_raw.xml \
  --profile original --fix-waist \
  --plan examples/euler/tray_transfer/outputs/blue_transfer_fixed_waist_candidate2/plan.json
```

不指定 `--output` 会生成新目录，保留旧实验。正常完成但验收失败返回 2；配置或执行异常返回非零并记录失败原因及夹具标记。当前复查预期失败。路径只绑定当前 XML、资源和初始布局，不具备随机化或视觉重规划能力。新代码增加了验收逻辑，因此新的结果结构会比旧记录多出搬运检查。

失败候选中 `offline_transfer_evidence.release_gap_m=0.02` 才是生成路点使用的松手间隙；`placement.release_clearance_m=0.005` 是早期预检配置的遗留字段，runner 不读取它来生成动作。后续重新生成可用计划时需要统一该元数据。

## 下一步

先解决抓点的可达性与稳定夹持，再重规划搬运。优先在离线副本中检查将蓝件起始位置适度移近机器人，能否使用更低、更居中的抓姿；不能直接复用现有路点或只改校验哈希。选出候选后先验证抬升和延长保持，再验证完整搬运。

cuRobo 的接入应继续使用同一组机器人、TCP、障碍物及关节限制；规划更快不能替代抓持力和接触质量验证。等完整任务通过，才加入起始位置随机化、重规划、图像与动作同步录制，制作 π0.5 训练数据。
