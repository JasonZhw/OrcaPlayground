# Agent-as-Policy 框架（药品分拣）

> 一句话：**大模型做它擅长的（看图、判断、决策），代码做它擅长的（几何、IK、执行、校验）**。
> 每个动作都返回结构化结果，失败码翻译成中文喂回模型 → 模型重新决策。不是脚本，是闭环。

---

## 一、整体结构

```
                     ┌─────────────────────────────┐
                     │  大模型（视觉决策大脑）        │
                     │  看画面 → 说理由 → 给动作     │
                     └──────────────┬──────────────┘
                                    │ 结构化动作 + 理由
                     ┌──────────────▼──────────────┐
                     │  执行工具层 fine_tools        │
                     │  每个动作返回 SkillResult     │
                     │  (ok / code / message)       │
                     └──────────────┬──────────────┘
                                    │ 失败码
                     ┌──────────────▼──────────────┐
                     │  恢复：失败码 → 中文提示      │
                     │  + 经验库 lessons 的历史成功  │
                     └──────────────┬──────────────┘
                                    │ 喂回 prompt
                                    └────► 回到大模型重新判断
```

每一轮都是：**推理 → 执行 → 调用工具 → 看结果 → 再推理**。

## 二、职责边界

| 能力 | 大模型 | 代码 | 理由 |
|---|---|---|---|
| 看图像认物体 | ✅ | | 视觉语义 |
| 定位大致坐标 | ✅ | | 单应接地后给 (x, y) |
| 决定抓哪件、放哪个筐 | ✅ | | 策略 |
| 判断是否对准 / 能否下放 | ✅ | 几何兜底 | 模型偶尔看错左右，几何是硬约束 |

| 到位校验 / 接触校验 | | ✅ | 传感器真值 |
| 搬运被挡怎么办 | ✅ | | 看画面判断横移还是抬高 |

## 三、一次完整循环（每个物体）

```
① locate            模型看俯视图 → 物体大致 (x, y)
   [推理] 物体中心 (x, y)；侧握/顶握，抓取点取后方/上方 N cm
② approach_xy       保持当前高度水平移到预备点 XY（不碰物体）
   approach         垂直到预备抓取点（抓取点上方 8cm）
   descend          垂直到抓取点，张开夹爪
③ align_grasp       循环：模型看腕部+俯视图 → left/right/forward/backward/grasp
   close            三段式闭合 → 接触确认 → 建立 carried 抓持关系
   test_lift        抬 3cm，物体跟着起来且仍接触 = 夹稳
④ locate            模型定位目标筐
   plan_placement   模型看筐里已有几件 → 决定这件放筐内哪个位置
   lift_safe        抬到筐口上方（释放点 +8cm）
   carry            水平搬运（补偿物体相对手腕的偏移）
   align_place      几何检查通过才放行；模型误判时按几何误差朝筐心微调
   release          当前位置直接释放
   settle           等 200 帧让物体落进筐底
   verify_placement 视觉 + 几何双校验
⑤ home              回初始位
```

## 四、失败恢复（本框架的核心）

### 4.1 失败码 → 中文提示

`skills.CODE_HINT` 把失败码翻译成人话，喂回模型：

| 失败码 | 含义 | 模型该怎么做 |
|---|---|---|
| `lost_grasp` | 夹住了但抬起来滑落 | 夹浅了，再前伸/下压一点重抓 |
| `ik_no_solution` | 该位姿 IK 解不出来 | 到极限了，换方向或直接 grasp |
| `plan_collision` | 路径撞到东西 | 绕开或抬高 |
| `missed_bin` | 释放时物体不在筐口范围 | 调整落点 |
| `tracking_error` | 伺服没跟上目标 | 多保持一会儿再判 |

### 4.2 经验库 lessons

`agent_out/lessons.json` 累积统计：

```json
{"ik_no_solution": {"grasp": {"worked": 5, "failed": 1},
                    "forward": {"worked": 0, "failed": 3}}}
```

下次遇到 `ik_no_solution`，prompt 里会多一行：

```
【历史经验】同类失败以前用这些动作奏效过：改做「grasp」成功过 5 次，这次可优先考虑。
```

**不训练模型，只累积统计**——跑得越多越懂这个任务。

### 4.3 不终止原则

以下情况全部**不终止任务**，一律反馈给模型重新规划：

- 模型输出无法解析（unknown）→ 提示格式要求，重新判断
- 微调失败（`ik_no_solution` / `plan_collision`）→ 反馈"到极限了，改判"
- 搬运被挡 → 模型决定横移/抬高，最多 6 次
- 夹持失败 → 张开、反馈、重新对齐重抓，最多 3 轮

## 五、工程 trick

| trick | 作用 |
|---|---|
| arm-only 模型 | 裁掉躯干/腿/头并关闭其碰撞体，避免手臂撞自己 |
| 手指全链接触豁免 | 侧握时手指中段碰目标物体不算碰撞 |
| 抓持关系 carried | 抬升/搬运时碰撞检查忽略"手-目标物体"接触 |
| 大跳降级小步 | `step_move_to` 失败时拆成 4cm 小步，每步重解 IK |
| 释放前检查接触 | 下放到筐底后物体被托住、接触自然松，那不是掉 |
| 物体偏移补偿 | 侧握物体挂在手腕旁 ~20cm，要让**物体**对准筐口而不是手腕 |
| 固定搬运朝向 | 夹住后手腕朝向锁定为抓取朝向，全程不转 |
| 到位容差 1.5cm | 高位置伺服有重力残差，多保持一会儿再判 |
| 几何优先放行 | 物体几何在筐口范围内才下放，不听模型主观判断 |
| 无高度上限 | 够不够得到交给 IK，失败由恢复逻辑接手 |
| 药盒自适应步长 | 顶握下压 2~6cm 跟随模型估计；药瓶侧握固定 6cm |
| 接着场景继续 | 已在筐内的物体自动跳过，不必重置 |

## 六、文件结构

```
examples/euler/medication_sorting/
├── agent_policy.py      入口：起仿真、构建工具、跑一轮
├── agentic_loop.py      ★ 主循环：逐物体「抓取 → 搬运 → 入框」+ 失败恢复
├── fine_tools.py        ★ 工具层：模型能调的每个动作（都返回 SkillResult）
├── skills.py            SkillResult / 失败码 / CODE_HINT
├── lessons.py           ★ 经验库：失败码 → 成功恢复动作
├── workflow.py          场景/几何：抓取点、放置点、碰撞检查、arm-only
├── planning.py          IK 求解、路径规划、抓取点搜索
├── execution.py         仿真推进、夹爪控制、到位校验
├── backend.py           大模型 API 封装
├── arm_only_model.py    裁模型（去躯干/腿/头）
├── mj_joint_strip.py    关节裁剪工具
├── visual_grounding.py  单应矩阵视觉接地
├── grasp_alignment.py   抓取对齐几何
└── playbook.py          专家示范回放
```

标注 ★ 的是本框架新增的核心文件。
