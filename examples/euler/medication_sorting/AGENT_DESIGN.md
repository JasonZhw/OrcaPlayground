# Agent-as-Policy 重构设计（分类任务）

> 任务性质：**分类（classification）** —— 把药瓶放进紫筐、药盒放进蓝筐。
> 设计取向：**agentic**（感知→决策→执行→观察→再决策），**不是 code-as-policy**（不让模型生成控制序列）。

---

## 一、任务定义（收敛版）

```
目标：四件物体全部进入正确的筐
  · 两只白瓶（calcium / melatonin） → 左侧紫筐
  · 两个蓝盒（pharyngitis / herbbox） → 右侧蓝筐

判定：每件物体的重心落在对应筐底范围内
完成：四件都正确入筐
```

**关键性质**：同类物体进**同一个筐**，所以「把 calcium 认成 melatonin」不影响任务成败。
模型只需区分 **瓶 vs 盒** 和 **紫筐 vs 蓝筐**，不需要读药名。

---

## 二、执行策略（分阶段演进）

### 阶段 1（当前）：固定顺序

```
左臂：calcium → melatonin      （都进紫筐）
右臂：pharyngitis → herbbox    （都进蓝筐）
总顺序：calcium → pharyngitis → melatonin → herbbox（两臂交替，避免互相等待）
```

**为什么固定顺序**：
- 消除一个决策维度，便于先验证「感知 + 抓取」链路
- agent 仍有真实决策：某件抓不到时要不要 skip、失败后要不要重试

### 阶段 2（后续）：agent 自主选顺序

固定顺序跑通、成功率稳定后，把「选哪件」交回 agent，观察它是否会做出更高效的安排（比如先抓离得近的）。

---

## 三、动作空间（agentic 设计）

### 核心原则

| 原则 | 说明 |
|---|---|
| **一次一个动作** | 每轮只输出一个 JSON，不生成序列、不写脚本 |
| **语义级** | 动作是「抓这件」，不是「把关节 X 转到 Y」 |
| **可观察** | 每个动作执行后都重新拍照，用结果驱动下一步 |
| **不可越权** | 模型无法指定坐标、角度、力、底座运动 |

### 三个动作（全部）

```json
{"action": "pick",   "object": "calcium"}
{"action": "skip",   "object": "melatonin"}
{"action": "finish"}
```

| 动作 | 语义 | 执行层做什么 |
|---|---|---|
| `pick` | 抓取该物体并放入它的目标筐 | 算抓取位姿 → 13 个角度逐个试 → 规划轨迹 → 执行 → 真值校验 |
| `skip` | 放弃该物体 | 标记为不可达，继续下一件 |
| `finish` | 认为任务完成 | 退出循环 |

**注意**：`pick` 里**没有 yaw 参数**。角度可行性是纯几何信息，由执行层搜索（实测模型盲猜从未命中过正确角度）。

### 每轮的观测

```
① 3 张图（头部 / 左腕 / 右腕），512px 压缩
② 极简文本：
   任务描述
   本轮第几步
   已入筐：[...]
   待处理：[...]
   上次失败的物体和原因
   已试尽角度的物体（提示直接 skip）
```

### 每轮流程图

```
        ┌──────────────────────────────┐
        │  拍 3 张图                    │
        └───────────┬──────────────────┘
                    ↓
        ┌──────────────────────────────┐
        │  agent 决策（1 个 JSON）       │ ← 唯一需要模型的地方
        └───────────┬──────────────────┘
                    ↓
        ┌──────────────────────────────┐
        │  执行层：IK → 角度搜索 → 轨迹  │
        └───────────┬──────────────────┘
                    ↓
        ┌──────────────────────────────┐
        │  再拍 3 张图 + 真值            │
        └───────────┬──────────────────┘
                    ↓
        ┌──────────────────────────────┐
        │  agent 判断是否入筐            │ ← 视觉校验
        └───────────┬──────────────────┘
                    ↓ 回到顶部
```

## 四、能力边界（明确能做什么 / 不能做什么）

### 模型能做的

| 能力 | 依据 |
|---|---|
| 从图像区分瓶 / 盒 | 形状差异明显，实测可靠 |
| 判断哪个筐是紫 / 蓝 | 颜色鲜明 |
| 数还剩几件 | 计数 |
| 判断某件是否已入筐 | 看图判断 |
| 决定放弃某件 | 结合失败历史 |
| 决定何时结束 | 四件都完成 |

### 模型不能做的

| 禁止 | 原因 |
|---|---|
| 输出关节角 / 坐标 | 精度不够，且执行层有真值 |
| 输出抓取角度 | 几何可行性与视觉无关（实测 0 命中） |
| 输出控制序列 / 写代码 | 这是 code-as-policy，不是我们要的 |
| 控制底座 / 腿 / 腰 | 已通过关节裁剪物理移除 |
| 关闭碰撞检查 / 超速 | 安全约束不可越权 |

## 五、关节裁剪（用官方 `mj_joint_strip.py`）

### 官方工具做了什么

| 步骤 | 效果 |
|---|---|
| `plan_strip` | 按白名单挑出保留的关节 |
| `strip_xml` | 从 XML 删除其余关节 + 对应执行器 + 等式约束 + 传感器 |
| `bake_dropped_bodies` | 把被删 body 的位姿烘焙进父 body（位置不变） |
| `kill_stripped_collision` | 关掉被删 body 的碰撞几何 |
| `QposBridge.pad` | 渲染时把精简 qpos 补齐到完整维度 |

### 我们的配置（保留双臂）

```python
KEEP_BOTH_ARMS = (
    # 左臂 7 关节
    "left_shoulder_pitch_joint", "left_shoulder_roll_joint", "left_shoulder_yaw_joint",
    "left_elbow_joint", "left_wrist_roll_joint", "left_wrist_pitch_joint", "left_wrist_yaw_joint",
    # 右臂 7 关节
    "right_shoulder_pitch_joint", "right_shoulder_roll_joint", "right_shoulder_yaw_joint",
    "right_elbow_joint", "right_wrist_roll_joint", "right_wrist_pitch_joint", "right_wrist_yaw_joint",
    # 两个夹爪
    "gripper_l_inner_joint", "gripper_l_outer_joint",
    "gripper_r_inner_joint", "gripper_r_outer_joint",
)
```

### 预期收益

| 项 | 裁剪前 | 裁剪后（预估） |
|---|---|---|
| 关节数 njnt | 30 | 16 + 场景物体 |
| 执行器 nu | 45 | 20（14 臂 + 6 夹爪） |
| 底座自由度 | 6（需等式约束焊死） | **0（物理移除）** |
| 腿/腰漂移 | 实测 62 mm | **0** |
| 物理步进 | 全身体 | 只需算两条手臂 → 更快 |
| 确定性 | 受腿/腰下沉影响 | 完全确定 |

**这是替代我之前 `JointLock`（指令层拦截）的更彻底方案**——从模型里直接删掉，不存在"被驱动"的可能。

### 实施要点（已确认的技术细节）

1. **XML 来源**：`bridge.load_model_xml()` 返回的是**文件路径**，不是 XML 内容
2. **渲染必须补齐**：`bridge.render()` 需要完整 121 维 qpos，所以每次渲染前用 `QposBridge.pad()`
3. **场景物体是 foreign 关节**：会被保留，位置不受影响
4. **相机**：由 OrcaStudio 场景提供（模型内 `ncam=0` 时跳过检查）
5. **前置条件**：必须在 OrcaLab 已加载完整场景时执行（当前返回 `nq=7` 的桩模型，说明场景没加载）

| 现有 | 改动 |
|---|---|
| `JointLock`（指令层拦截 15 个执行器） | **替换为关节裁剪**（物理移除） |

| 视觉校验 | 保留（模型判断 + 真值对照） |
| 兜底策略 | 保留（模型失败 → 启发式 → 保证有动作） |
